# FORENSIC AUDIT — STAGE 89
## Controlled Structured Trace Integration

Status: PROVISIONED — execution disabled

### Objective
Integrate the Stage 88 structured trace into the existing observation/reconciliation cycle without introducing trading behavior.

### Integration boundary
The trace is downstream of state reconciliation and upstream of any future replay comparator. It records the observed state and lifecycle/decision outputs generated by the existing observers.

Required order:

`Market Update -> Reconcile -> Observer Evaluation -> Structured Trace Capture -> Panel Render`

No `OrderSend`, `OrderModify`, `OrderClose`, `OrderCloseBy` or pending deletion is introduced by this stage.

### Canonical evidence rule
The trace must distinguish:

- OBSERVED: directly read from the MT4 state/lifecycle.
- DERIVED: calculated by an existing observer from observed state.
- UNRESOLVED: no causal rule established by forensic replay.
- REFUTED: rule rejected by the forensic audit.

### Event priority
When several observer conditions appear in one tick, the trace records all eligible observations and leaves causal arbitration to the replay comparator. It must not silently convert observer coexistence into a proven execution priority.

### Replay purpose
The resulting trace is intended to become the canonical machine-readable input for Stage 90 backtest comparison. The comparison will seek the first causal divergence rather than matching final balance alone.

### Safety gate
`EXECUTION_ENABLED = false`

This stage is provisioning and instrumentation only.
